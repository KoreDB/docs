KoreDB includes four extensions by default and provides an extension API for loading additional functionality at runtime.

## Built-in extensions

KoreDB 0.11.3 and default native source builds, including **Release builds** and the
**Node.js package** (`@koredb/koredb`), statically link these extensions:

| Extension | Functionality |
| --------- | ------------- |
| [algo](/extensions/algo) | Graph algorithms |
| [fts](/extensions/full-text-search) | Full-text search using BM25 |
| [json](/extensions/json) | JSON types, functions, and file operations |
| [vector](/extensions/vector) | Vector indexes and similarity search |

They are part of the database library and load automatically when a database is opened.
No extension download, extension server, `INSTALL`, or `LOAD` is required.

Existing scripts can keep their installation and loading statements. For a built-in extension,
these statements succeed with an informational result and skip downloading or loading it again:

```cypher
INSTALL fts;
LOAD EXTENSION fts;
```

The same behavior applies to `algo`, `json`, and `vector`. Extension names are case-insensitive,
and the short form `LOAD fts` also succeeds. In Node.js, this works through both the async
and sync APIs, including prepared statements and multi-statement queries.

Use `CALL SHOW_LOADED_EXTENSIONS() RETURN *;` to inspect the actual build. Built-in extensions
have an `extension source` of `STATIC LINK` and no external library path.

Custom builds can have a different extension set. The standalone extension artifact build
(`BUILD_EXTENSION_RELEASE=TRUE`) is separate from a normal Release database or Node.js build.

:::caution[Note]
KoreDB no longer provides an official extensions server, from where you can directly install the official extensions.

For older versions or extensions that are not built in, you have to set up a local extension server.
The instructions of setting up a local extension server can be found [here](/extensions#host-your-own-extension-server).
:::

## Available extensions

The following extensions are currently implemented:

| Extension | Built in by default | Description |
|----------|----------|----------|
| [algo](/extensions/algo) | Yes | Graph algorithms |
| [azure](/extensions/azure) | No | Scan from Azure Blob Storage and Azure Data Lake Storage (ADLS) |
| [delta](/extensions/attach/delta) | No | Scan data from Delta Lake tables |
| [duckdb](/extensions/attach/duckdb) | No | Scan data from an attached DuckDB database |
| [fts](/extensions/full-text-search) | Yes | Perform full-text search using BM25 |
| [httpfs](/extensions/httpfs) | No | Read and write files over HTTP(S) protocol. Also used for [attaching a remote KoreDB database](/extensions/attach/koredb). |
| [iceberg](/extensions/attach/iceberg) | No | Scan data from Iceberg tables |
| [json](/extensions/json) | Yes | Scan and manipulate JSON data |
| [llm](/extensions/llm) | No | Generate text embeddings using external provider APIs |
| [neo4j](/extensions/neo4j) | No | Migrate data from Neo4j into KoreDB |
| [postgres](/extensions/attach/postgres) | No | Scan data from an attached PostgreSQL database |
| [sqlite](/extensions/attach/sqlite) | No | Scan data from an attached SQLite database |
| [unity](/extensions/attach/unity) | No | Scan data from Unity Catalog tables |
| [vector](/extensions/vector) | Yes | Perform vector similarity search |

## Using extensions in KoreDB

This section describes how to use officially supported extensions in KoreDB.

### List available extensions

You can list all available official extensions by running:

```cypher
CALL SHOW_OFFICIAL_EXTENSIONS() RETURN *;
```

### Install an extension

Only extensions that are not [built in](/extensions#built-in-extensions) require installation.
For built-in extensions, `INSTALL` succeeds without downloading anything, even if a `FROM` repository is specified.

Official extensions can be installed from a [local extension server](/extensions#host-your-own-extension-server) by running the `INSTALL` command.

```cypher
INSTALL <EXTENSION_NAME> FROM 'http://localhost:8080/';
```
You only need to install an extension once.

### Update an extension

If you run the `INSTALL` command for an extension that is already installed,
the second install command will not perform any action.

If you want to re-download an extension for any reason, for example if the extension is not working
properly, you can use the `UPDATE` command for a separately installed extension:

```cypher
UPDATE <EXTENSION_NAME>;
```

Built-in extensions are updated by upgrading the KoreDB package or rebuilding the database library.
`UPDATE` and `FORCE INSTALL` also skip downloads for built-in extensions.

### Load an extension

Built-in extensions load automatically. `LOAD` and `LOAD EXTENSION` for their names succeed
without loading another library or registering the extension twice.

You must load separately installed extensions before you can use them:

```cypher
LOAD <EXTENSION_NAME>;
```

Official extensions can be loaded by simply specifying the extension name.
For example, after installing the `httpfs` extension:

```cypher
LOAD EXTENSION httpfs;
```
If you want to load an extension you have compiled yourself, you can specify the path to the compiled library.
For example, to load a self-compiled `json` extension:

```cypher
LOAD EXTENSION 'extension/custom_json/build/libjson.koredb_extension';
```

### List loaded extensions

You can view all your loaded extensions by running:

```cypher
CALL SHOW_LOADED_EXTENSIONS() RETURN *;
```

:::note[Note]
Extensions are scoped to the session within which they are loaded. Thus, the `LOAD` command must be
executed for every new CLI session or client script invocation for separately installed extensions.
Built-in extensions are loaded automatically in each database instance.
:::


### Uninstall an extension

You can uninstall separately installed extensions if you don't need them anymore by using the `UNINSTALL` command:

```cypher
UNINSTALL <EXTENSION_NAME>;
```
:::note[Note]
Uninstalling a currently loaded extension won't affect the running database instance, but you won't be able to load it again in a new KoreDB instance until it's reinstalled.
Built-in extensions are part of the database library and cannot be removed with `UNINSTALL`.
:::

### Host your own extension server

You can host your own extension server for KoreDB using Docker.

The extension server is based on NGINX and is hosted on [GitHub](https://ghcr.io/koredb/extension-repo). You can pull the Docker image and run it in your environment:

```bash
docker pull ghcr.io/koredb/extension-repo:latest
docker run -d -p 8080:80 ghcr.io/koredb/extension-repo:latest
```

In this example, the extension server will be available at `http://localhost:8080`. You can then install extensions from your server by appending the `FROM` clause to the `INSTALL` command:

```cypher
INSTALL <EXTENSION_NAME> FROM 'http://localhost:8080/';
```
