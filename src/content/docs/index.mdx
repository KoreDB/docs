Welcome to the KoreDB docs!

:::note[Storage format compatibility]
**KoreDB will always maintain compatibility with the Kuzu 0.11.x storage format.**
This commitment applies to all future KoreDB releases. Storage changes must preserve
compatibility with existing Kuzu 0.11.x database files.
:::

KoreDB is an embedded graph database built for query speed and scalability. It is optimized for
handling complex join-heavy analytical workloads on very large graphs and has the following core features:

- Property Graph data model and Cypher query language
- Embedded (in-process) integration with applications
- Columnar disk-based storage
- Columnar and compressed sparse row-based (CSR) adjacency list and join indices
- Vectorized and factorized query processing
- Novel and efficient join algorithms
- Multi-core query parallelism
- Serializable ACID transactions

## Why KoreDB?

Although there are many graph database management systems (GDBMSs) in the market today,
KoreDB stands apart because its design and implementation address specific trade-offs that
make it a compelling choice for analytical query workloads on large graphs.
Below, we list some of the key reasons why you should consider using KoreDB.

### Performance and scalability

KoreDB builds on Kuzu's research-driven design for scalable graph analytics.
The upstream Kuzu team's work on storing and querying large graphs provides the foundation
for KoreDB's performance and scalability.

### Usability

KoreDB is built for industry use cases. It implements a suite of features that lower the barrier of entry
for modeling your data as a graph and querying it in an expressive [graph query language](https://github.com/opencypher/openCypher).
Because KoreDB is an embedded database, it runs within your application process, making it easy to set up and use KoreDB.
KoreDB does not require installing any external dependencies or managing it as a DBMS server.

### Interoperability

KoreDB is designed to be highly interoperable with a variety of external formats and columnar or relational stores,
including Parquet, Arrow, DuckDB, and more. This allows you to easily move your existing data to and from KoreDB,
making it a great choice for graph data science, machine learning, and analytics use cases.

### Structured property graph model

The data model in KoreDB is based on the property graph model, together with some structure (including
node and relationship tables, and a pre-defined schema). This makes it flexible and intuitive to model your existing
data as a graph, while also being smart enough to optimize query performance and perform vectorized
operations at scale.

### Open source

KoreDB is open source and has a permissive MIT license, which allows you to build commercial and proprietary
applications on top of it. Check out [our GitHub repo](https://github.com/KoreDB/koredb) and try out KoreDB.
And while you're there, consider giving us a star and spreading the word!
